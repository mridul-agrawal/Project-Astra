Four needs identical, four different — and the four differences came to two arguments, one overload and one accessor.

What it replaced

From 2026-08-28 until this change, the hub carried GurukulScreenFade: its own canvas, its own black image, its own alpha coroutine, and a copy of the clamp comment. ScreenFader had been doing that job since 2026-06-06.

Its header explained the duplication this way:

"Its own thing rather than the shared ScreenFader… that one marks itself DontDestroyOnLoad, so a hub-spawned copy would follow the player into the battle map"

True of a copy — but the hub never needed to spawn one. SceneLoader creates exactly one at boot and it is alive and idle throughout the hub. The obstacle was reach, not lifetime, and reach is an accessor. The second reason given, the 0.35s duration, was real and is now an argument.

Deleted with it: the hub scene's FadeOverlay object and the builder code that created it.
