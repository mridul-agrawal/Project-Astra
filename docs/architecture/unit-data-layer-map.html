Why this hurts without a tool — the flaws, in one place

Each maps to a badge above. These are the problems the master editor should erase.

  1. 1Faceless stats. StatArray renders as an unlabeled int[9] in the inspector — you edit stats by counting array indices.
  2. 2Items live in code. ~28 weapons/consumables are C# factories, not assets — invisible to a designer.
  3. 3Manual registration. UnitDatabase (and MapCatalog) are hand-maintained; omissions fail silently at runtime, not authoring time.
  4. 4Blank enemy stats. Enemy assets ship all-zero — a landmine the faceless inspector hides.
  5. 5Duplicated truth. TestUnit repeats definition fields, editable independently of the asset.
  6. 6Unauthored stubs. Abilities, weapon ranks, and supports/bonds have no data yet — only enums & free-text ids.
WHERE THIS IS HEADING

In the proposed Data Hub, each blue ScriptableObject becomes one left-rail tab; every → reference becomes an inline dropdown with a + New that creates the target and returns; auto-registration removes the amber registry step; and the red/amber badges become a live Problems panel.
