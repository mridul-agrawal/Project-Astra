Before you begin

The shared unit graph must exist once per project: Project Astra ▸ Animation ▸ Build Unit Locomotion Controller (creates Assets/Animation/UnitLocomotion.controller). Already built here — skip it. Every character you place also needs a UnitDefinition registered in the UnitDatabase (via Project Astra ▸ Data Hub).

Act I

Prepare your animations

1

Put your art in the right folder

Drop every sheet under Assets/Art/Animation/… (any subfolders). Anything there imports automatically crisp — Point filter, 32 pixels-per-unit, uncompressed. Keep your base-ground PNG aside for now; it goes in through the Map Editor in Step 5.

Sheet rules that matter:

  • Base ground PNG — width & height must be multiples of 32 (1 tile = 32 px) and at least 15 tiles (480 px) wide. Paint the river region into it as a still.
  • Unit frames — one direction/state per row or per sheet; frame counts may differ per state.
  • Decoration / river — a single strip or grid of frames.
2

Slice each sheet into named frames

Open Project Astra ▸ Animation ▸ Animation Studio → Slice tab. Drag in a sheet, then:

  • Set Columns / Rows (or tick Size by cell pixels).
  • River: tick Tileable (FullRect). Trees / flowers: set Pivot → Bottom-Center so they sit on the ground.
  • Set the Base Name — this is the part everything hinges on (see the rule below).
  • Click Slice.

The naming rule — read this

The frame names are the wiring. A unit's frames must be named exactly by state, and a decoration's frames by one base word. The Base Name you type when slicing becomes that prefix. If you name an idle sheet protagonist_idle, the builder won't find it — it's looking for idle.

Unit direction → state name. Slice each of a unit's six sheets with these exact base names:

Your sheetBase Name to typeProduces
Idleidleidle_0, idle_1…
Running Uprun_nrun_n_0…
Running Rightrun_erun_e_0…
Running Downrun_srun_s_0…
Running Leftrun_wrun_w_0…
Selectedselectedselected_0…

Six separate single-row sheets are perfectly fine — the builder scans the whole folder and groups by these prefixes, so mixed frame counts (say 5 / 10 / 6…) work. It's the names, never the arrangement, that matter. (One 6-row sheet? Tick Unit sheet and it labels the rows for you.)

3

Build the animators

Still in Animation Studio:

  • Unit Controller tab → Character Name, Frames Folder = the folder holding that unit's six sliced sheets, fps → Build. Out comes the six clips + an override controller in Assets/Animation/Units/<name>/.
  • Deco Controller tab → one per tree / flower / bird / river: Name, Frames Folder, fps → Build → a looping controller in Assets/Animation/Environment/<name>/.

Watch the Preview panel loop each one before you move on.

4

Give each unit its animation

Open a character's UnitDefinition (Data Hub or Inspector) and set Map Animation to that character's override controller. Leave it empty and the unit simply uses its static sprite — nothing breaks.

Act II

Build the map

5

Create it & lay the ground

Open Project Astra ▸ Map ▸ Map Editor:

  1. New… → save the MapData (default Assets/ScriptableObjects/Map/Maps).
  2. Identity — a Name and a unique Map Id (no spaces, e.g. map2_riverford).
  3. Base Art — Import PNG… your ground, then Fit Size To Art.
6

Paint terrain & place units

  • Terrain tab — paint every cell. Paint the river cells Water / River — that's what pathfinding reads and what the river auto-fit detects later. Border the map with Wall.
  • Units tab — pick a Unit (from the database) + a Team, then click cells to place. Click a placed unit to remove it.
Act III

Bring it to life

Why this act works differently — read once

Terrain and units are a fixed shape, so the Map Editor handles them as data. Decorations are the opposite — an open creative domain (a bird on a random arc, a leaf that falls now and then, a per-map glow, a bespoke script). So you don't paint them into data; you build them as a normal prefab, in a real scene, with full Unity freedom — and the map just points to that prefab. The Environment Builder is that scene, with your actual map shown underneath as a backdrop so placement is exactly what the player will see.

7

Open the builder & load your map as a backdrop

Open Project Astra ▸ Map ▸ Environment Builder, then:

  1. Set Map to the MapData you just built (it's remembered next time).
  2. Click Open Builder Scene — the first time, this creates Assets/Scenes/MapEnvironmentBuilder.unity and opens it; after that it just re-opens it.
  3. Click Load Backdrop. Your map's real base art, a grid overlay, and colored unit markers appear. This backdrop is view-only — it's never saved into your prefab; it's just there so you author against the true map, edges and all.

If a pivot warning appears — fix it before placing anything

The base art needs a Bottom-Left pivot to sit on the grid. If the builder warns it's Center, click Fix base-art pivot to BottomLeft, then Load Backdrop again. (If you skip this, the art — and everything you place against it — will be offset in the real game.)

8

Place one decoration — the core loop

Click New to create the empty Environment root. Everything you add lives under it. To add one animated decoration (a tree, a flower, a bird):

  1. Right-click Environment ▸ Create Empty (or drag a sliced sprite into the scene and parent it under Environment). Name it (e.g. Tree_A).
  2. Add a Sprite Renderer; set its Sprite to the deco's first frame and its Sorting Layer from the table below.
  3. Add an Animator; set its Controller to that deco's controller (built in Act I, Deco Controller tab).
  4. Position it anywhere — drag it in the Scene view. Off-map is fine: a tree can hang 20% past the edge and only the on-screen part shows.
  5. Add any behaviour components from the recipe table to give it life.

Duplicate the object (Ctrl+D) for more of the same kind, then reposition — that's how you fill a meadow fast.

The base-layer river — one click

With the Environment root present, click Add River Patch (auto-size to water band). It creates a tiled sprite on Ground (order 10) sized to the Water/River cells you painted in Step 6. Select it and assign your tileable river sprite + its animator controller. Because it's tiled and on Ground, it reads as the ground itself flowing.

Particles, effects & per-map post-processing

It's a normal prefab — add a Shuriken ParticleSystem (fireflies, mist, embers; set its Renderer's Sorting Layer to match). For a map-wide look, add a URP Volume (Global) as a child, pointing at a cloned VolumeProfile with Bloom/Vignette dialed in — it only affects the map while this prefab is loaded. One catch: turn the BattleMap camera's Post Processing toggle on (off by default) or no Volume shows.

10

Preview, then save it to the map

  1. Press Play right in the builder scene — everything animates (loops, arcs, one-shots, particles) with no game boot needed. Tune and repeat until it feels right.
  2. Click Save → MapData.environmentPrefab. The Environment root is saved to Assets/Prefabs/Environment/<mapId>.prefab and wired into your MapData; the backdrop is left out automatically.

Come back any time: pick the map, Load Backdrop, Load Existing — your prefab re-opens for editing. One prefab per map.

Act IV

Play it

11

Register & load in-game

Back in the Map Editor, make sure the map is Saved, its Validation is clear (empty id, off-map units, unresolved unit ids), and it's Registered In Catalog. Then choose how to load it:

  • Quick look — open Assets/Scenes/BattleMap.unity, select the MapBootstrapper object, set its Fallback Map Data to your new map, and press Play. (A few harmless singleton warnings log when the scene runs standalone — ignore them.)
  • Real campaign play — open the Campaign asset, add a step with kind = Battle and Map Id = your map's id, then play from the front end to reach it cleanly.

Press Play and it all comes together: units idle, run in four directions, and glow when hovered; foliage sways out of sync; a bird crosses the sky over the fighters; and the river flows across the ground.

Appendix

When something won't animate

Build does nothing / "no frames found"

Almost always the frame names. The builder needs a unit's sprites named idle_N / run_n_N / run_e_N / run_s_N / run_w_N / selected_N, and a deco's named <base>_N. A character prefix (hero_idle_0) or a friendly word (running_down instead of run_s) both break the match. Re-slice with the exact Base Name from the table in Step 2.

Unit shows a static sprite in play

Its UnitDefinition ▸ Map Animation is empty, or the override controller wasn't built. Do Steps 3–4.

River renders as one stretched frame, not tiling

The river sheet wasn't sliced with Tileable (FullRect) ticked. Re-slice it that way and rebuild the controller. On the River object, the SpriteRenderer Draw Mode must be Tiled (the Add River Patch button sets this for you).

Bird renders behind units

Set the bird's SpriteRenderer Sorting Layer to Sky (it sits above Units).

Environment doesn't appear in the real battle

Confirm Save → MapData.environmentPrefab wired the prefab (check the MapData's Environment Prefab field). A new map grid built via Create Map Grid already has its Environment container; older scenes may need it wired once.

Two honest caveats

Combat-screen animations aren't built yet. Everything here is on-map animation; the Fire-Emblem-style battle screen still uses a placeholder.

Placeholder art is currently wired to the protagonist and to Map 1. When you author real content, just overwrite those fields — nothing else changes.

Every animator here is a plain asset you can open, preview, and swap — build once, reuse across maps.
